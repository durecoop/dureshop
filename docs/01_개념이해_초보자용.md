## 1. 왜 Git을 사용하나요?

### 1.1 Git 없이 개발하면 생기는 문제

```
📁 프로젝트 폴더
├── index.html
├── index_최종.html
├── index_최종_수정.html
├── index_최종_수정_진짜최종.html
├── index_최종_수정_진짜최종_v2.html
└── index_백업_20260129.html
```

**문제점:**
- 어떤 파일이 진짜 최신인지 모름
- 언제 무엇을 바꿨는지 기억 안 남
- 여러 사람이 같이 작업하면 파일이 엉킴
- 예전 버전으로 돌아가기 어려움

### 1.2 Git을 사용하면

```
📁 프로젝트 폴더
└── index.html  ← 항상 하나의 파일만!

📜 Git이 기억하는 변경 이력:
├── 2026-01-29: 헤더 색상 변경 (이지원)
├── 2026-01-28: 로고 이미지 추가 (김철수)
├── 2026-01-27: 메뉴 구조 변경 (이지원)
└── 2026-01-26: 최초 생성 (이지원)
```

**장점:**
- 파일은 하나, 변경 이력은 Git이 관리
- 누가, 언제, 무엇을 바꿨는지 기록됨
- 언제든 과거 버전으로 되돌릴 수 있음
- 여러 사람이 동시에 작업 가능

## 2. Git이란 무엇인가요?

### 2.1 한 줄 정의
> **Git = 파일의 변경 이력을 기록하고 관리하는 프로그램**

### 2.2 비유로 이해하기

#### 📚 책의 수정 이력과 비슷합니다

```
원고 작성 (1판)
    ↓
오타 수정 (2판)
    ↓
그림 추가 (3판)
    ↓
목차 변경 (4판)  ← 현재
```

Git은 이런 "수정 이력"을 자동으로 기록해주는 시스템입니다.

#### 🎮 게임의 세이브 포인트와 비슷합니다

```
[세이브 1] 마을 출발
    ↓
[세이브 2] 동굴 입구
    ↓
[세이브 3] 보스 앞  ← 잘못하면 여기로 돌아옴
    ↓
[세이브 4] 보스 클리어
```

Git의 "커밋"은 게임의 "세이브 포인트"와 같습니다.
실수하면 이전 세이브로 돌아갈 수 있습니다.

### 2.3 Git이 설치되는 위치

```
내 컴퓨터
├── Git 프로그램 (설치됨)
└── 프로젝트 폴더
    ├── .git/ (숨김 폴더 - Git이 이력을 저장하는 곳)
    ├── index.html
    └── style.css
```

Git은 **내 컴퓨터**에 설치되어 실행됩니다.

## 3. GitHub란 무엇인가요?

### 3.1 한 줄 정의
> **GitHub = Git으로 관리하는 프로젝트를 인터넷에 저장하는 서비스**

### 3.2 비유로 이해하기

#### ☁️ 클라우드 저장소와 비슷합니다

| 서비스 | 저장 대상 |
|--------|-----------|
| 네이버 클라우드 | 사진, 동영상, 문서 |
| 구글 드라이브 | 사진, 동영상, 문서 |
| **GitHub** | **코드 + 변경 이력** |

#### 📧 이메일 vs 웹메일과 비슷합니다

```
Outlook (내 컴퓨터) ←→ Gmail (인터넷)
   Git (내 컴퓨터)  ←→ GitHub (인터넷)
```

- Git = 내 컴퓨터에서 작업
- GitHub = 인터넷에 백업 & 공유

### 3.3 GitHub를 사용하는 이유

1. **백업**: 컴퓨터가 고장나도 코드가 안전함
2. **공유**: 다른 컴퓨터에서도 같은 코드로 작업 가능
3. **협업**: 여러 사람이 함께 개발 가능
4. **이력**: 모든 변경 기록이 온라인에 보관됨

## 4. Git vs GitHub 차이점

### 4.1 한눈에 비교

| 구분 | Git | GitHub |
|------|-----|--------|
| **종류** | 프로그램 | 웹 서비스 |
| **위치** | 내 컴퓨터 | 인터넷 (github.com) |
| **역할** | 변경 이력 관리 | 온라인 저장 & 공유 |
| **비용** | 무료 | 무료 (기본) |
| **필수 여부** | 필수 | 선택 (하지만 권장) |

### 4.2 그림으로 이해하기

```
┌─────────────────────────────────────────────────────────────┐
│                        인터넷                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              GitHub (github.com)                     │   │
│  │         원격 저장소 (Remote Repository)               │   │
│  │                                                      │   │
│  │   우리 프로젝트: durecoop/dureshop                    │   │
│  └─────────────────────────────────────────────────────┘   │
│                         ↑↓                                  │
│                    push(올리기)                              │
│                    pull(받기)                                │
└─────────────────────────────────────────────────────────────┘
                          ↑↓
┌─────────────────────────────────────────────────────────────┐
│                     내 컴퓨터                                │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                   Git                                │   │
│  │         로컬 저장소 (Local Repository)                │   │
│  │                                                      │   │
│  │   C:\Users\이지원\DURE_SHOP                          │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

## 5. 핵심 개념 6가지

### 5.1 저장소 (Repository)

> **저장소 = Git이 관리하는 프로젝트 폴더**

```
일반 폴더:        Git 저장소:
📁 my-project     📁 my-project
├── index.html    ├── .git/  ← 이 폴더가 있으면 Git 저장소!
└── style.css     ├── index.html
                  └── style.css
```

- **로컬 저장소**: 내 컴퓨터에 있는 저장소
- **원격 저장소**: GitHub에 있는 저장소

### 5.2 커밋 (Commit)

> **커밋 = 변경사항을 저장소에 기록하는 것 (세이브 포인트)**

```
파일 수정
    ↓
커밋 (기록)  →  "헤더 색상을 녹색으로 변경"
    ↓
파일 수정
    ↓
커밋 (기록)  →  "로고 이미지 추가"
```

- 커밋할 때 **메시지**를 함께 남김 (무엇을 바꿨는지)
- 커밋 = 게임의 세이브 포인트

### 5.3 푸시 (Push)

> **푸시 = 내 컴퓨터의 커밋들을 GitHub에 올리는 것**

```
내 컴퓨터 (Git)                    GitHub
┌──────────────┐                ┌──────────────┐
│ 커밋1        │                │              │
│ 커밋2        │  ── push →    │ 커밋1        │
│ 커밋3        │                │ 커밋2        │
└──────────────┘                │ 커밋3        │
                                └──────────────┘
```

### 5.4 풀 (Pull)

> **풀 = GitHub의 변경사항을 내 컴퓨터로 받는 것**

```
내 컴퓨터 (Git)                    GitHub
┌──────────────┐                ┌──────────────┐
│ 커밋1        │                │ 커밋1        │
│ 커밋2        │  ← pull ──    │ 커밋2        │
│ 커밋3 (새로) │                │ 커밋3        │
└──────────────┘                └──────────────┘
```

- 다른 컴퓨터에서 작업한 내용을 받을 때 사용
- 매일 작업 시작 전에 pull 하는 것이 좋음

### 5.5 클론 (Clone)

> **클론 = GitHub의 저장소를 내 컴퓨터로 복제하는 것**

```
GitHub                           내 컴퓨터
┌──────────────┐                ┌──────────────┐
│ 프로젝트     │  ── clone →   │ 프로젝트     │
│ 전체 복사    │                │ (똑같이)     │
└──────────────┘                └──────────────┘
```

- 새 컴퓨터에서 처음 프로젝트를 받을 때 사용
- 프로젝트 전체 + 모든 변경 이력을 복제

### 5.6 요약 표

| 용어 | 의미 | 방향 | 비유 |
|------|------|------|------|
| **Repository** | 저장소 | - | 프로젝트 폴더 |
| **Commit** | 변경 기록 | 로컬 | 게임 세이브 |
| **Push** | 올리기 | 로컬 → GitHub | 업로드 |
| **Pull** | 받기 | GitHub → 로컬 | 다운로드 |
| **Clone** | 복제 | GitHub → 로컬 | 전체 복사 |

## 6. 브랜치란 무엇인가요?

### 6.1 한 줄 정의
> **브랜치 = 독립적인 작업 공간 (평행 세계)**

### 6.2 비유로 이해하기

#### 🌳 나무의 가지와 비슷합니다

```
         ○ 로고 수정 (feature/logo)
        /
───○───○───○───○ 메인 줄기 (master)
            \
             ○───○ 주문페이지 개발 (feature/order-renewal)
```

- **master(메인)**: 안전한 원본 코드
- **feature/xxx**: 새 기능을 개발하는 가지

#### 📝 문서 작업과 비슷합니다

```
[원본 기획서]
     │
     ├── [기획서_마케팅검토용] - 마케팅팀이 수정 중
     │
     └── [기획서_개발검토용] - 개발팀이 수정 중

나중에 → 원본에 합침
```

### 6.3 왜 브랜치를 사용하나요?

**브랜치 없이 작업하면:**
```
A가 수정 → 오류 발생 → 전체 사이트 문제!
```

**브랜치를 사용하면:**
```
A가 브랜치에서 수정 → 오류 발생 → 브랜치만 문제, 원본은 안전!
    ↓
오류 수정 후 → 원본에 합침
```

### 6.4 우리 프로젝트의 브랜치

```
master (원본 - 안전한 버전)
   │
   └── feature/order-renewal (주문 페이지 개발 중)
           │
           └── 여기서 마음껏 수정해도 master는 안전!
```

## 7. 개발 작업 흐름 이해하기

### 7.1 전체 흐름도

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 아침에 출근                                               │
│    └── git pull (다른 사람이 수정한 내용 받기)                 │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. 파일 수정                                                 │
│    └── VS Code 등 에디터에서 코드 수정                        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. 변경사항 확인                                             │
│    └── git status (뭐가 바뀌었나 확인)                        │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 커밋 (저장)                                               │
│    └── git add . → git commit -m "메시지"                    │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. GitHub에 올리기                                           │
│    └── git push                                              │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 6. FTP 서버에 업로드 (선택)                                   │
│    └── 개발 서버에서 실제로 확인하고 싶을 때                    │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│ 7. 결과 확인                                                 │
│    └── 브라우저에서 dev.ecoop.or.kr 접속                      │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 각 단계 설명

| 단계 | 하는 일 | 왜 필요한가 |
|------|---------|-------------|
| Pull | 최신 코드 받기 | 다른 사람 작업 내용 동기화 |
| 수정 | 코드 변경 | 실제 개발 작업 |
| Status | 변경 확인 | 뭐가 바뀌었는지 확인 |
| Commit | 변경 저장 | 세이브 포인트 만들기 |
| Push | GitHub 업로드 | 백업 & 공유 |
| FTP | 서버 업로드 | 실제 사이트에 반영 |

## 8. FTP란 무엇인가요?

### 8.1 한 줄 정의
> **FTP = 파일을 서버로 전송하는 프로토콜 (방법)**

### 8.2 비유로 이해하기

```
내 컴퓨터                          웹 서버
┌──────────┐                    ┌──────────┐
│ 파일들   │  ── FTP 전송 →    │ 파일들   │
└──────────┘                    └──────────┘
                                     ↓
                               사용자가 웹사이트 접속
```

- 내 컴퓨터의 파일을 → 웹 서버로 올리는 것
- 올린 파일이 웹사이트에 반영됨

### 8.3 Git vs FTP 차이

| 구분 | Git + GitHub | FTP |
|------|--------------|-----|
| 목적 | 코드 버전 관리 & 백업 | 서버에 파일 전송 |
| 이력 관리 | O (누가, 언제, 뭘 바꿨는지) | X |
| 롤백 | 쉬움 | 어려움 (백업 필요) |
| 용도 | 개발자 간 협업 | 서버 배포 |

### 8.4 우리의 작업 흐름에서 FTP 위치

```
1. 코드 수정
2. Git 커밋 (변경 이력 저장)
3. GitHub Push (백업)
4. FTP 업로드 (서버에 반영) ← 여기서 FTP 사용
5. 웹사이트에서 확인
```

## 9. 우리 프로젝트의 전체 구조

### 9.1 전체 시스템 구조

```
┌─────────────────────────────────────────────────────────────────┐
│                         인터넷                                   │
│                                                                  │
│   ┌──────────────┐              ┌──────────────┐                │
│   │   GitHub     │              │   웹 서버    │                │
│   │  (코드 백업)  │              │  (FTP 서버)  │                │
│   │              │              │              │                │
│   │ durecoop/    │              │ 100.100.1.54 │                │
│   │ dureshop     │              │              │                │
│   └──────────────┘              └──────────────┘                │
│          ↑                             ↑                        │
│       push/pull                       FTP                       │
│          │                             │                        │
└──────────┼─────────────────────────────┼────────────────────────┘
           │                             │
           │      ┌──────────────┐       │
           └──────│   내 컴퓨터   │───────┘
                  │              │
                  │  DURE_SHOP/  │
                  │  (작업 폴더)  │
                  └──────────────┘
```

### 9.2 각 요소의 역할

| 요소 | 역할 | 주소 |
|------|------|------|
| **내 컴퓨터** | 코드 수정 | C:\Users\이지원\DURE_SHOP |
| **GitHub** | 코드 백업 & 이력 관리 | github.com/durecoop/dureshop |
| **FTP 서버** | 개발 서버에 파일 배포 | 100.100.1.54 |
| **웹 서버** | 실제 웹사이트 운영 | dev.ecoop.or.kr |

### 9.3 작업 시나리오 예시

**시나리오: 주문 페이지 버튼 색상 변경**

```
1. [내 컴퓨터] order.css 파일에서 버튼 색상 수정
       ↓
2. [내 컴퓨터] git add, git commit (세이브)
       ↓
3. [내 컴퓨터 → GitHub] git push (백업)
       ↓
4. [내 컴퓨터 → FTP] curl로 파일 업로드 (서버 반영)
       ↓
5. [브라우저] dev.ecoop.or.kr에서 확인
       ↓
6. 문제 있으면? → Git으로 이전 버전 복원 후 다시 FTP 업로드
```

## 용어 사전 (가나다 순)

| 용어 | 영어 | 의미 |
|------|------|------|
| 로컬 | Local | 내 컴퓨터 |
| 브랜치 | Branch | 독립적인 작업 공간 |
| 원격 | Remote | 인터넷 (GitHub) |
| 저장소 | Repository | Git이 관리하는 폴더 |
| 커밋 | Commit | 변경사항 저장 (세이브) |
| 클론 | Clone | 저장소 전체 복제 |
| 풀 | Pull | 원격에서 받기 |
| 푸시 | Push | 원격으로 올리기 |
