## 1. 시작하기 전에

### 1.1 터미널(명령 프롬프트) 열기

**Windows:**
1. `Win + R` 키를 누름
2. `cmd` 입력 후 엔터
3. 또는 VS Code에서 `` Ctrl + ` `` 로 터미널 열기

**Mac:**
1. `Cmd + Space` → "터미널" 검색
2. 또는 VS Code에서 `` Ctrl + ` ``

### 1.2 기본 명령어 형식

```bash
명령어 옵션 대상

예시:
git status          # git = 명령어, status = 하위명령
git add index.html  # add = 하위명령, index.html = 대상
```

### 1.3 경로 이동

```bash
# 폴더로 이동
cd 폴더경로

# 예시
cd C:\Users\이지원\DURE_SHOP

# 현재 위치 확인
pwd
```

## 2. 최초 1회: 새 컴퓨터 설정

> 새 컴퓨터에서 처음 개발을 시작할 때 **한 번만** 하면 됩니다.

### 2.1 단계별 실습

#### Step 1: Git 설치 확인

```bash
git --version
```

**예상 결과:**
```
git version 2.43.0
```

❌ 오류가 나면: https://git-scm.com 에서 Git 설치

---

#### Step 2: 프로젝트 저장할 폴더로 이동

```bash
cd C:\Users\이지원\Desktop
```

또는 원하는 폴더로 이동

---

#### Step 3: GitHub에서 프로젝트 복제

```bash
git clone https://github.com/durecoop/dureshop.git DURE_SHOP
```

**예상 결과:**
```
Cloning into 'DURE_SHOP'...
remote: Enumerating objects: 50, done.
remote: Counting objects: 100% (50/50), done.
Receiving objects: 100% (50/50), 250.00 KiB | 1.00 MiB/s, done.
```

---

#### Step 4: 프로젝트 폴더로 이동

```bash
cd DURE_SHOP
```

---

#### Step 5: Git 사용자 설정

```bash
git config user.email "durecoop@gmail.com"
git config user.name "durecoop"
```

**확인:**
```bash
git config user.email
git config user.name
```

---

#### Step 6: 개발 브랜치로 전환

```bash
git checkout feature/order-renewal
```

**예상 결과:**
```
Switched to branch 'feature/order-renewal'
```

---

#### Step 7: 설정 완료 확인

```bash
git status
```

**예상 결과:**
```
On branch feature/order-renewal
Your branch is up to date with 'origin/feature/order-renewal'.

nothing to commit, working tree clean
```

✅ **설정 완료!** 이제 개발을 시작할 수 있습니다.

## 3. 매일: 기본 작업 흐름

> 매일 개발할 때 반복하는 작업입니다.

### 3.1 작업 시작 (아침)

#### Step 1: 프로젝트 폴더로 이동

```bash
cd C:\Users\이지원\DURE_SHOP
```

---

#### Step 2: 최신 코드 받기

```bash
git pull
```

**예상 결과:**
```
Already up to date.
```
또는
```
Updating a1b2c3d..e4f5g6h
Fast-forward
 order_step1.jsp | 10 +++++-----
 1 file changed, 5 insertions(+), 5 deletions(-)
```

---

### 3.2 파일 수정 후 저장

#### Step 1: 변경된 파일 확인

```bash
git status
```

**예상 결과:**
```
On branch feature/order-renewal
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
        modified:   WEB-INF/jsp/shop/order/order_step1.jsp

no changes added to commit (use "git add" to track)
```

빨간색으로 표시된 파일 = 수정했지만 아직 저장 안 함

---

#### Step 2: 변경 내용 미리보기 (선택)

```bash
git diff
```

수정한 내용이 표시됨 (종료: `q` 키)

---

#### Step 3: 변경 파일 스테이징 (저장 준비)

**방법 A: 특정 파일만**
```bash
git add WEB-INF/jsp/shop/order/order_step1.jsp
```

**방법 B: 특정 폴더 전체**
```bash
git add WEB-INF/jsp/shop/order/
```

**방법 C: 변경된 모든 파일**
```bash
git add .
```

---

#### Step 4: 스테이징 확인

```bash
git status
```

**예상 결과:**
```
Changes to be committed:
        modified:   WEB-INF/jsp/shop/order/order_step1.jsp
```

초록색으로 표시됨 = 저장 준비 완료

---

#### Step 5: 커밋 (저장)

```bash
git commit -m "feat: 쿠폰 선택 UI 개선"
```

**예상 결과:**
```
[feature/order-renewal abc1234] feat: 쿠폰 선택 UI 개선
 1 file changed, 10 insertions(+), 5 deletions(-)
```

💡 **커밋 메시지 작성 팁:**
- `feat:` 새 기능
- `fix:` 버그 수정
- `style:` 디자인 변경
- `docs:` 문서 수정

---

#### Step 6: GitHub에 올리기

```bash
git push
```

**예상 결과:**
```
Enumerating objects: 5, done.
Counting objects: 100% (5/5), done.
Writing objects: 100% (3/3), 300 bytes | 300.00 KiB/s, done.
To https://github.com/durecoop/dureshop.git
   abc1234..def5678  feature/order-renewal -> feature/order-renewal
```

✅ **저장 완료!** GitHub에 백업되었습니다.

---

### 3.3 한 줄 요약 (매일 반복)

```bash
git pull                                    # 1. 최신 받기
# ... 파일 수정 ...

git push                                    # 5. GitHub 올리기
```

## 5. 되돌리기 (롤백) 명령어

> 실수했을 때 이전 상태로 돌아가는 방법입니다.

### 5.1 아직 커밋 안 한 변경사항 취소

**상황:** 파일을 수정했는데 다 지우고 원래대로 돌리고 싶어요

**특정 파일만 되돌리기:**
```bash
git checkout -- WEB-INF/jsp/shop/order/order_step1.jsp
```

**모든 변경 되돌리기:**
```bash
git checkout -- .
```

⚠️ **주의:** 수정한 내용이 모두 사라집니다!

---

### 5.2 스테이징 취소 (add 취소)

**상황:** `git add` 했는데 취소하고 싶어요

```bash
git reset HEAD 파일경로
```

**예시:**
```bash
git reset HEAD WEB-INF/jsp/shop/order/order_step1.jsp
```

**모든 파일 스테이징 취소:**
```bash
git reset HEAD .
```

---

### 5.3 마지막 커밋 취소 (파일 유지)

**상황:** 커밋했는데 메시지를 잘못 썼어요, 파일은 그대로 두고 커밋만 취소

```bash
git reset --soft HEAD~1
```

- `HEAD~1` = 마지막 1개 커밋
- `--soft` = 파일 변경은 유지

---

### 5.4 마지막 커밋 완전 취소

**상황:** 커밋한 내용 전부 없던 일로 하고 싶어요

```bash
git reset --hard HEAD~1
```

⚠️ **주의:** 수정한 파일도 모두 사라집니다!

---

### 5.5 특정 시점으로 파일 복원

**상황:** 3일 전 버전의 파일로 돌아가고 싶어요

#### Step 1: 커밋 이력 확인
```bash
git log --oneline
```

**결과 예시:**
```
b0f0a37 docs: 개발환경 가이드
8425fee feat: order_step1 리뉴얼
4fb2dda 초기 커밋
```

#### Step 2: 원하는 커밋 해시 복사 (예: 4fb2dda)

#### Step 3: 해당 시점의 파일로 복원
```bash
git checkout 4fb2dda -- WEB-INF/jsp/shop/order/order_step1.jsp
```

#### Step 4: 복원한 파일 커밋
```bash
git add .
git commit -m "rollback: order_step1 이전 버전으로 복원"
git push
```

---

### 5.6 FTP 서버 롤백

**상황:** FTP에 올린 파일에 문제가 있어요

```bash
# 1. Git에서 이전 버전 복원
git checkout 이전커밋해시 -- 파일경로

# 2. FTP에 다시 업로드
curl -u tester2:1234 -T "파일경로" "ftp://100.100.1.54/경로"
```

## 6. 브랜치 관련 명령어

### 6.1 현재 브랜치 확인

```bash
git branch
```

**결과:**
```
  master
```

### 6.2 모든 브랜치 확인 (원격 포함)

```bash
git branch -a
```

---

### 6.3 브랜치 전환

```bash
git checkout 브랜치이름
```

**예시:**
```bash

git checkout feature/order-renewal   # 다시 개발 브랜치로
```

### 6.4 새 브랜치 만들기

```bash

```

**예시:**
```bash

```

---

### 6.5 새 브랜치를 GitHub에 올리기

```bash
git push -u origin 브랜치이름
```

**예시:**
```bash

```

## 7. 상황별 해결 방법

### 7.1 "Your branch is behind" 메시지

**상황:**
```
Your branch is behind 'origin/feature/order-renewal' by 2 commits
```

**해결:**
```bash
git pull
```

---

### 7.2 "Changes not staged for commit" 메시지

**상황:** 커밋하려는데 변경사항이 없다고 함

**해결:**
```bash
git add .                        # 먼저 스테이징
git commit -m "메시지"           # 그 다음 커밋
```

---

### 7.3 "Please commit your changes before switching branches"

**상황:** 브랜치를 바꾸려는데 변경사항이 있어서 안 됨

**해결 방법 1: 커밋하기**
```bash
git add .
git commit -m "임시 저장"
git checkout 다른브랜치
```

**해결 방법 2: 임시 보관 (stash)**
```bash
git stash                        # 변경사항 임시 보관
git checkout 다른브랜치          # 브랜치 전환
git checkout 원래브랜치          # 다시 돌아오기
git stash pop                    # 보관한 변경사항 복원
```

---

### 7.4 "rejected - non-fast-forward"

**상황:** push가 거부됨

**해결:**
```bash
git pull --rebase
git push
```

---

### 7.5 잘못된 커밋 메시지 수정

**상황:** 방금 커밋한 메시지를 고치고 싶어요

```bash
git commit --amend -m "새로운 메시지"
```

⚠️ 이미 push 했다면 사용 자제

## 8. 명령어 요약표

### 8.1 기본 명령어

| 명령어 | 설명 | 사용 시점 |
|--------|------|-----------|
| `git status` | 현재 상태 확인 | 수시로 |
| `git pull` | 최신 코드 받기 | 작업 시작 전 |
| `git add .` | 변경 파일 스테이징 | 커밋 전 |
| `git commit -m "메시지"` | 변경사항 저장 | 작업 완료 시 |
| `git push` | GitHub에 올리기 | 커밋 후 |
| `git log --oneline` | 커밋 이력 확인 | 이력 확인 시 |

### 8.2 되돌리기 명령어

| 명령어 | 설명 | 주의사항 |
|--------|------|----------|
| `git checkout -- 파일` | 수정 취소 | 변경 사라짐 |
| `git reset HEAD 파일` | 스테이징 취소 | - |
| `git reset --soft HEAD~1` | 커밋 취소 (파일 유지) | - |
| `git reset --hard HEAD~1` | 커밋 완전 취소 | 변경 사라짐 |
| `git checkout 해시 -- 파일` | 특정 버전 복원 | - |

### 8.3 브랜치 명령어

| 명령어 | 설명 |
|--------|------|
| `git branch` | 브랜치 목록 |
| `git checkout 브랜치명` | 브랜치 전환 |
| `git checkout -b 브랜치명` | 새 브랜치 생성 |
| `git push -u origin 브랜치명` | 브랜치 업로드 |

### 8.4 FTP 명령어

| 명령어 | 설명 |
|--------|------|
| `curl -u user:pass -T "파일" "ftp://서버/경로"` | 업로드 |
| `curl -u user:pass "ftp://서버/파일" -o 로컬파일` | 다운로드 |
| `curl -u user:pass "ftp://서버/폴더/"` | 목록 확인 |
